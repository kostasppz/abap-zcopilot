# Local ABAP Expert RAG integration

ABAP Guardian can delegate AI generation to the local ABAP Expert service
while retaining Guardian's deterministic analyzer and Eclipse API. This mode
uses the existing Chroma database, PDF/Word readers, knowledge directory and
Ollama models from the ABAP Expert project.

## Request path

```text
Eclipse / ADT
  -> http://localhost:8001 (ABAP Guardian API and deterministic analyzer)
  -> http://abap-ai:8000/api/chat (local ABAP Expert RAG)
  -> http://ollama:11434 (local chat and embedding models)
```

The containers communicate only through the Docker Compose network. Ports
8000 and 8001 are bound to `127.0.0.1`, so neither local service is exposed to
the LAN. All model inference stays in the local ABAP Expert/Ollama stack.

## Directory layout

Place the repositories beside each other:

```text
<user-directory>/
  abap-agent/
    agent.py
    compose.yaml
    knowledge/
    vector_db/
  abap-zcopilot/
    Dockerfile
    ai-gateway/
    analyzer-core/
```

Clone Guardian if it is not present:

```powershell
cd "$HOME"
git clone https://github.com/kostasppz/abap-zcopilot.git
```

## Compose configuration

Copy `docs/examples/compose.local-rag.yaml` to the ABAP Expert directory as
`compose.yaml`, or add its `abap-guardian` service and health check to the
existing file. The Guardian build context `../abap-zcopilot` assumes the
sibling-directory layout above.

Select exact local model names in the Compose environment. Confirm them with:

```powershell
docker exec abap-ollama ollama list
```

Start or rebuild the complete stack:

```powershell
cd "$HOME\abap-agent"
docker compose up -d --build
```

Rebuild the Chroma index after adding or changing knowledge files:

```powershell
docker compose exec abap-ai python agent.py index
```

## Verification

Check the RAG agent:

```powershell
Invoke-RestMethod http://localhost:8000/api/status | ConvertTo-Json -Depth 5
```

Check Guardian:

```powershell
Invoke-RestMethod http://localhost:8001/health | ConvertTo-Json -Depth 5
Invoke-RestMethod http://localhost:8001/api/v1/models | ConvertTo-Json -Depth 5
```

Guardian health should report `llmProvider` as `abap-agent`, `llmAvailable`
as `true`, and `analyzerAvailable` as `true`.

In Eclipse, open **Window -> Preferences -> ABAP Guardian**, set the service
URL to `http://localhost:8001`, enable AI enhancement and select **Test
Connection**. The Copilot view continues to use Guardian's stable API, while
answers are generated by the local ABAP Expert RAG service.

## Responsibilities

- Guardian owns deterministic findings, line positions, editor annotations,
  the Copilot API and safe correction preview.
- ABAP Expert owns document parsing, Chroma retrieval, source selection and
  calls to the local Ollama chat and embedding models.
- Ollama stores and runs the models. Indexing knowledge does not train or
  modify the model itself.

The adapter consumes the ABAP Expert service's NDJSON stream and deliberately
does not expose backend exception details to Eclipse. If the agent or model is
unavailable, Guardian returns its normal sanitized AI-unavailable response;
deterministic analysis remains available.

To move the same stack to an always-on NVIDIA VM and connect Eclipse through
authenticated HTTPS, follow [`dedicated-gpu-vm.md`](dedicated-gpu-vm.md).
